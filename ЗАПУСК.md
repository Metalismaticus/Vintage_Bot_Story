# Vintage Bot Story — как запустить бота

> **Имя сменилось 17.08.2026.** Приложение звалось `TradeBot`, теперь —
> **Vintage Bot Story**: папка и файл программы `VintageBotStory`, для людей
> «Vintage Bot Story» с пробелами. Библиотека осталась `VsBotKit`. Если в
> старых записях и журналах вам попадётся `TradeBot` — это то же самое.

## Коротко

Один файл под вашу систему. Ни .NET, ни батника, ни командной строки не
нужно. Нужна **установленная Vintage Story** — бот не отдельная игра, а клиент
к ней, и он берёт из установки её код, реестр блоков и библиотеку сжатия.

| Система | Что запускать |
|---|---|
| Windows | `VintageBotStory.exe` — двойной щелчок |
| Linux | `VintageBotStory` — двойной щелчок или `./VintageBotStory` |
| macOS (M1–M4) | `VintageBotStory` |
| macOS (Intel) | `VintageBotStory` |

Раздавать нужно **всю папку**, а не один файл: рядом лежит `presets` — готовые
боты, которые видно в окне управления.

## Тому, кто просто хочет играть

1. Поставьте **Vintage Story** (обычную игру).
2. Скачайте папку под свою систему и запустите файл внутри. Ставить .NET не
   нужно: он уже внутри файла.
3. Откроется окно управления в браузере. Там выбираете готового бота, вводите
   имя (или логин и пароль), адрес сервера — и нажимаете **Вход**.

**Запуск бота — не запуск входа на сервер.** Программа поднимается и ждёт вас
в окне; на сервер она полезет только когда вы нажмёте кнопку.

Окно живёт **только на этой машине** (`127.0.0.1`), и вход в него закрыт
ключом, который рождается заново при каждом запуске. С другой машины — через
`ssh -L 42462:127.0.0.1:42462 пользователь@сервер`.

Если игра стоит в необычном месте, скажите об этом заранее:

```bash
export VINTAGE_STORY=/путь/к/игре        # Windows: set VINTAGE_STORY=C:\путь
```

### Что бот делает при первом запуске

Кладёт рядом с собой папку `Lib` и в неё одну библиотеку — `libzstd` (около
1 МБ), взятую из вашей установки игры. Это не самодеятельность: сервер шлёт
реестр блоков сжатым, разжимает его код самой игры, а тот ищет библиотеку
именно в папке рядом с запущенной программой. Заодно появляются `bot.json`
(настройки с комментариями) и `logs/` — журнал.

Если положить не вышло (папка только для чтения), бот скажет об этом **и не
пойдёт дальше**, а не полезет на сервер, чтобы упасть на первом сжатом пакете.

### Пароль администратора для окна

На своей машине ключа в ссылке хватает. На сервере — нет: ссылку приходится
копировать из консоли через ssh каждый раз, она оседает в истории браузера и
в списке недавних вкладок, а сменить её можно только перезапуском бота.
Поэтому окно можно закрыть **паролем**, и тогда открывается страница входа, а
ключ в адресе перестаёт что-либо значить.

Три способа, по убыванию силы:

```bash
# 1. Готовый отпечаток — так задают пароль службе.
#    В systemd-файле оседает отпечаток, войти по нему нельзя.
export VS_PANEL_PASSWORD_HASH='pbkdf2-sha256$210000$…$…'

# 2. Сам пароль переменной окружения.
export VS_PANEL_PASSWORD='ваш-пароль'
```

```jsonc
// 3. Спросить при запуске — ввод без эха, для запуска руками из терминала
{ "panel": { "use": true, "askPassword": true } }
```

Имена переменных можно сменить в `bot.json`: `panel.passwordEnv` и
`panel.passwordHashEnv`. **Самого пароля в `bot.json` нет и быть не может** —
этот файл показывают, копируют и пересылают вместе с ботом.

При запуске бот говорит в консоль, чем именно заперто окно:
`Окно управления: вход по паролю: пароль взят из VS_PANEL_PASSWORD`.

**Если пароль просили, а взять его не вышло** (мусор вместо отпечатка, одни
пробелы в переменной, «спросить при запуске» в службе без консоли) — окно
**не откроется вовсе**, и бот скажет почему. Это нарочно: пустить по ключу
того, кто просил пароль, значит оставить дверь распахнутой, а человека — в
уверенности, что заперли.

### Карта в окне — доп настройка, по умолчанию выключена

Карта живёт во вкладке **«Задачи и карта»** (отдельной вкладки «Карта» больше
нет — её слили с задачами) и показывает, где бот, где дом, где склад и где он
видел руду. Своей памяти у карты нет: она рисует то, что бот и так знает, и
теми же **игровыми** координатами, какими он говорит в журнале.

**Отметить дом прямо на карте.** Щёлкните по месту — карта покажет выбранную
точку и посчитает дорогу. Рядом с ней стоит список точек роли («Дом», «Склад» и
всё, что роль назвала точкой) и кнопка **«Записать в настройку»**: нажали —
точка легла в настройку роли, ушла в пресет и **сразу доехала до бота**, без
перезапуска. Те же поля числами есть во вкладке **«Настройка роли»**: «Склад» и
«Дом» стоят там первыми, одно под другим. Там же, а не на общей вкладке, стоит и
«Пост» стражника.

Карточка «Точки роли» на вкладке «Общие настройки» — для ПРОЧИХ точек, тех, что
роль назвала сама и что не попали на её собственную вкладку. У ролей поставки
таких нет ни одной, и карточка говорит это прямо: она называет вкладку, где
точки этой роли вправду крутят, а не печатает «точек у этой роли нет».

В списке предлагаются только точки в **игровых** координатах — теми и говорит
карта. Точку в мировых координатах окно не предложит и скажет об этом: перепутать
их значит увести бота на полмиллиона блоков.

Выключена она нарочно. Бот чаще всего живёт на сервере, где окно неделями
никто не открывает, а карта работает **на каждый опрос страницы**: перебирает
память руды (до 4096 клеток), точки склада и книгу встреч. Там, где на неё
никто не смотрит, это чистая трата памяти и работы.

```jsonc
{ "panel": { "use": true, "map": true } }
```

Или флагом запуска: `--map` / `--no-map`. Включить и выключить можно и прямо
в окне — галкой на вкладке; выбранное ложится в `bot.json`.

При включённом **серверном режиме** (`serverMode.use`) карта продолжает
работать, но её потолки урезаны — 40 клеток руды вместо 200 и 10 мест встреч
вместо 50, — и она говорит об этом на самой вкладке. Память бота при этом
целая: урезан только показ.

**Места встреч с живыми людьми — отдельный выключатель, тоже выключенный:**

```jsonc
{ "panel": { "use": true, "map": true, "mapPeople": true } }
```

Флаг запуска — `--map-people`. Включённое, оно показывает **только имя и
место последней встречи**. Ни времени встречи, ни того, сколько раз виделись,
ни того, здоровался ли бот, наружу не уходит: книга встреч — записи о живом
человеке, который о них не знает и согласия не давал. Окно живёт на петле и
никуда ничего не отправляет, а само включение уходит в журнал отдельной
строкой и в строку запуска: `…, карта С ИМЕНАМИ ВСТРЕЧЕННЫХ ЛЮДЕЙ`.

### Иконки предметов — доп настройка, делается один раз

В клетках инвентаря (вкладка «Состояние и вещи») стоят **имена словами**. Картинки бот
показать может, но **нарисовать не может никогда** — и это не лень, а
устройство игры: предмет в Vintage Story — объёмная модель, и то, что вы
видите в ячейке, каждый кадр рисует видеокарта. У безголового бота видеокарты
нет. Подсунуть вместо иконки текстуру нельзя: у медного топора она — ровный
оранжевый квадрат слитка, и рюкзак из таких квадратов читался бы как «полный
рюкзак меди».

Зато нарисовать их может **графический клиент игры**, и у него для этого есть
своя команда. Выгружаете один раз, кладёте папку рядом с ботом — и клетки
становятся картинками. Дальше бот к игре за этим не обращается вовсе.

**Всё разом — одной командой:**

1. Запустите обычную игру и войдите в любой мир (проще всего в свой
   одиночный). Права администратора не нужны: это команда клиента, не сервера.
2. Откройте чат и наберите:

   ```
   .blockitempngexport all 100
   ```

   * `all` — **берите его.** Так выгружается всё, и только так вы получите
     картинки сундука, ящика, шкафа, ведра, пирога и фонаря (см. рамку ниже).
   * `inv` — только то, что игра показывает во вкладках творческого инвентаря.
     Файлов меньше, но **дыры незаметные и обидные**.
   * `100` — сторона картинки в точках. Можно опустить (тогда те же 100).
   * Есть и третий довесок — домен (`.blockitempngexport all 100 game`), он
     оставляет только ванильные вещи и отсекает модовые.
3. Игра ответит в чат: `Ok, exported to <полный путь>`. Обычно это папка
   `icons` внутри установленной игры —
   `C:\Users\<вы>\AppData\Roaming\Vintagestory\icons`. Внутри `block\` и
   `item\`.
4. **Копировать больше не нужно**: бот смотрит в эту папку игры сам, последней
   по списку. Копия нужна только если вы хотите держать свой, отдельный набор
   картинок (или бот живёт на другой машине) — тогда положите папку `icons`
   туда, куда показывает **окно управления**: вкладка «Состояние и вещи»,
   раскладка «Как получить картинки предметов», поле с путём и кнопкой
   «Скопировать путь». Своя папка старше игровой.

   > ⚠️ **НЕ КЛАДИТЕ `icons` В ПАПКУ СБОРКИ.** Живая потеря 18.08: 18 560
   > выгруженных картинок лежали в
   > `VintageBotStory\bin\Debug\net10.0\icons` — то есть внутри каталога, который
   > пересборка (а у хозяина бота — распаковка новой версии поверх старой)
   > стирает целиком. Их стёрли, и возвращать было нечего.
   >
   > Поэтому у бота, **запущенного из сборки**, первым местом теперь стоит папка
   > **рядом с проектом** — там же, где лежит `presets`:
   > `<корень с исходниками>\icons`. У этого проекта это
   > `…\<папка проекта>\icons`, а не `…\<папка проекта>\VintageBotStory\icons`: всё, что лежит
   > внутри папки проекта, MSBuild подбирает заводским правилом, и восемнадцать
   > тысяч png стали бы восемнадцатью тысячами лишних записей на каждую сборку.
   >
   > Точный путь спрашивать не надо — его показывает то самое поле в окне.
   > Обычную установку (распакованный архив, контейнер) это не касается вовсе:
   > там всё как было.
5. Обновите страницу окна. Ждать перезапуска бота не надо: папку он
   перечитывает сам. Обычно это 20 секунд: раз в двадцать секунд бот сверяет
   времена каталогов и обходит тысячи файлов, только если что-то и правда
   добавилось или пропало. Windows про свежий файл иногда молчит (время
   каталога она обновляет лениво), поэтому есть страховка: **не позже чем через
   5 минут** папка обходится целиком, что бы эти времена ни говорили.

**Сколько это стоит по оперативке — числом, а не на глаз.** Сами картинки бот в
памяти **не держит вовсе**: файл читается на запрос окна и тут же
отпускается. Держится только опись имён — по строке на файл. На папке из
18 560 картинок это **2,5 МБ** (замерено). Для сравнения, там же и в то же
время: модель мира — десятки мегабайт (392 чанка, разжатых до 98 МБ, если
тронуть каждый), имена предметов из файлов игры — 6,2 МБ, подписи к настройкам
в окне — 4,3 МБ. Свои числа по этой машине бот показывает во вкладке
**«Память»**: строка «Опись картинок» стоит рядом со строкой «Модель мира».
Поэтому отдельного «режима без картинок» нет: выключать нечего.

> ⚠️ **Почему именно `all`, а не `inv` — живой случай 16.08.** Картинки были
> выгружены с `inv`, папка полна (8582 файла), а в клетке вместо фонаря стояло
> словом `lantern-large-up`. Дело не в поиске файла: файла не существовало
> вовсе — как и **ни одного** `chest-*`, `crate-*`, `cabinet-*`, `bucket-*`,
> `pie-*`. Причина в самой выгрузке: `inv` берёт блок, только если у него
> непустой `CreativeInventoryTabs`, а у этих блоков вкладки пустые — их место в
> творческом инвентаре задано готовыми стопками (`creativeinventoryStacks`),
> и выгрузка их просто не видит. То есть `inv` молча теряет ровно те вещи,
> которыми полон любой склад.
>
> *Проверено по коду: `VintagestoryLib 1.22.6`,
> `Vintagestory.Client.SystemClientCommands.OnRenderBlockItemPngs`, и по
> `assets/survival/blocktypes/metal/lantern.json` (`creativeinventory: {  }` +
> `creativeinventoryStacksByType`).*

**По одной вещи**, если нужна пара картинок, а не всё:

```
.exponepng code item flint
.exponepng code block rock-granite
.exponepng hand              — то, что сейчас в руке
```

Порядок слов именно такой: сперва `code`, потом `item`/`block`, потом сам код.

⚠️ **У `.exponepng hand` есть подвох** (проверено по коду игры): вид вещи она
не выставляет, и картинка ложится в `icons\block\` **даже для предмета** —
если только раньше в этом же запуске игры вы не звали `.exponepng code
item …`. Не появилась картинка после `hand` — переложите файл из
`icons\block\` в `icons\item\`.

⚠️ **Второй подвох, тоже у одиночной выгрузки:** у нескольких предметов в коде
есть косая черта (`clutter-art/bottle`, `clutter-skull/humanoid`). Общая
выгрузка меняет её на дефис и кладёт файл спокойно, а одиночная пишет путь как
есть — и спотыкается, потому что подпапку под неё игра не создаёт. Нужны такие
— берите общую выгрузку либо создайте подпапку (`icons\item\clutter-art\`)
руками. Бот ищет оба написания, так что найдёт файл в любом случае.

**Не путайте с `.exportlod2`** — она выгружает 32×32 текстуры для дальней
прорисовки, а не иконки.

**Как бот ищет файл.** По тем же правилам, по каким их кладёт игра: домен из
кода отбрасывается, блок ищется только в `icons/block/`, предмет только в
`icons/item/`. В чужую папку бот не заглядывает нарочно: один и тот же код
бывает и блоком, и предметом — это разные вещи с разными картинками. Среди
корневых кодов игры 1.22.6 таких восемь (`candle`, `cheese`, `egg`, `leather`,
`ore`, `paper`, `saltpeter`, `clutter`), а с их разновидностями пар больше.
Иначе в рюкзаке оказалась бы не та вещь, которая там лежит.

**Если папки нет или в ней нет нужного файла** — ничего не ломается: в клетке
остаётся имя словом, ровно как сейчас. Внизу вкладки бот пишет одной строкой,
откуда взяты картинки и сколько их, — или почему их нет, и про конкретную вещь
тоже: он называет те самые имена файлов, которых не нашёл.

**Где бот ищет папку `icons` — по порядку.** Побеждает **первая, в которой
и правда есть png**; пустая папка дорогу следующей не закрывает.

1. То, что сказано переменной окружения `VSBOT_ICONS` (см. ниже).
2. **Рядом с проектом** — только если бот запущен ИЗ ПАПКИ СБОРКИ
   (`…\bin\Debug\net10.0`). Тогда это папка над проектом, там же, где `presets`.
   Ради этого пункт и заведён: всё, что лежит в `bin`, стирает пересборка, и
   так уже пропали 18 560 картинок. У обычной установки этого места нет вовсе —
   у неё сборки нет.
3. Папка состояния бота — там же, где `bot.json`.
4. Папка рядом с исполняемым файлом.
5. **Папка самой игры** — `…\Vintagestory\icons`, куда `.blockitempngexport`
   и кладёт выгрузку. Последней нарочно: свой набор картинок старше игрового.

Пункты 3 и 4 при обычной установке — **одна и та же папка**, и бот называет её
один раз: два одинаковых пути подряд читались бы как два разных места.

Пункт 5 и есть ответ на «расположение для папок иконок странное, так точно
нужно?» — **не нужно**. Обязательного в этом ничего нет; при обычной установке
достаточно выгрузить картинки в игре и ничего никуда не копировать.

**Старые места никуда не делись.** У кого картинки уже лежат рядом с ботом или
в папке игры — у того ничего не сломалось: список только удлинился сверху, а
пустая новая папка дорогу старой не закрывает.

**Держите картинки в другом месте** — скажите об этом переменной окружения:

```
VSBOT_ICONS=/путь/к/icons
```

Она нужна там, где рядом с ботом писать нельзя, где бот живёт на другой машине,
чем игра, или где папку удобнее держать на общем томе (Docker — см. `VSBOT_STATE`
ниже).

*Проверено по сборкам игры 1.22.6 (`VintagestoryLib.dll`,
`Vintagestory.Client.SystemClientCommands`), а не по памяти и не по вики.*

## Арендованный сервер, где есть только ssh

Здесь честно, по шагам, включая то, чего мы за вас не сделаем.

### Что туда нужно положить

1. **Бота** — папку `out/linux-x64` (один файл + `presets`). Собирается на
   любой машине, в том числе на вашей домашней Windows.
2. **Файлы игры.** Без них бот не запустится: он грузит `VintagestoryAPI.dll`,
   `VintagestoryLib.dll`, моды из `Mods` и библиотеки из `Lib`.

Про второй пункт — подробно, потому что это главная работа:

```bash
# со своей машины, где игра установлена
rsync -av --exclude assets ~/.config/Vintagestory/ сервер:/srv/vintagestory/
ssh сервер 'echo export VINTAGE_STORY=/srv/vintagestory >> ~/.profile'
```

* **Вся установка** — около 910 МБ, из них 799 МБ это `assets`.
* **Без `assets`** — около 111 МБ, и бот с ними работает: проверено запуском
  на папке, из которой `assets` вырезаны. Расплата одна и её видно сразу —
  вместо человеческих названий предметов в окне и в журнале будут коды
  (`game:ingot-copper` вместо «слиток меди»).
* Копировать надо игру **под Linux**, а не под Windows: в `Lib` лежат
  библиотеки той системы, где игра установлена.

**Чего мы не умеем и не обещаем:** скачать игру на сервер за вас. Vintage
Story платная, ключ ваш, и загрузка идёт из личного кабинета. Мы не проверяли,
хватит ли бесплатного серверного архива игры вместо клиентского — там есть и
`VintagestoryAPI.dll`, и `VintagestoryLib.dll`, но живьём мы этого не пробовали
и утверждать не будем.

### Библиотека сжатия на Linux

Отдельного разговора почти не требует: игровой код на Linux сперва ищет
**системную** `libzstd.so.1`, и на любом обычном сервере она уже стоит. Если
нет — `apt install libzstd1` (Debian/Ubuntu) или `dnf install libzstd`
(Fedora). Своя копия рядом с ботом — запасной путь, он появляется сам.

### Docker

`Dockerfile` в корне. Собирается из уже готового бинарника: собрать бота
ВНУТРИ контейнера нельзя — для компиляции нужны .dll игры, а их в образе нет
и не будет.

```bash
./publish.sh linux-x64
docker build -t vsbot .
docker run --rm -it --network host \
    -v /srv/vintagestory:/game:ro \
    -v /srv/vsbot-data:/data \
    -e VS_PANEL_PASSWORD='пароль' \
    vsbot
```

**Что лежит в `/data`.** Всё, что бот пишет сам: `bot.json`, `botsession.json`
(ключ сессии), `botjobs.json`, `botmeetings.json`, журналы и свои пресеты. Это
задаёт `ENV VSBOT_STATE=/data` в `Dockerfile` — переменная, которую бот
слушает **первой**, до всех проверок. Раньше там стояла `XDG_STATE_HOME`, и
она не работала: её бот смотрит только когда рядом с собой писать нельзя, а в
контейнере `/app` записываем — то есть настройки и ключ сессии ложились внутрь
образа и пропадали при каждой пересборке. Теперь переживают.

**Готовые пресеты остаются в `/app/presets`** — они едут с программой, а не с
состоянием. Положи их в `/data` — подключённый том закрыл бы их собой. Бот
смотрит обе папки: свои пресеты пишет в состояние, готовые читает рядом с
программой; одноимённый свой перебивает готовый.

**Честно про `--network host`.** Окно управления слушает только петлю
(`127.0.0.1`) — это закон проекта, а не настройка. У контейнера со своей сетью
петля своя, и обычная публикация порта (`-p 42462:42462`) до окна не достаёт.
Поэтому либо `--network host` (работает на Linux), либо **докер здесь просто
не нужен**: один самодостаточный файл плюс `ssh -L` делают ровно то же самое и
без лишнего слоя. Мы держим `Dockerfile` для тех, у кого весь хостинг устроен
контейнерами, а не потому, что так лучше.

**И честно: `docker build` по этому файлу мы не запускали ни разу** — на
машине, где он писался, движок Docker не поднялся. Проверили только, что
базовый образ `mcr.microsoft.com/dotnet/runtime-deps:10.0` существует и собран
на Ubuntu (значит, `apt` и пакет `libzstd1` — те самые). Всё остальное там —
рассуждение по разобранным фактам. Это заготовка, а не готовое решение.

## Живой стенд: `стенд.ps1` — сервер, боты и опыты сами

> Раздел для тех, кто правит код. Самого стенда, `стенд-опыты.txt` и тестового
> сервера в публичном репозитории нет — они живут только в рабочем.

```powershell
powershell -ExecutionPolicy Bypass -File .\стенд.ps1              # один бот
powershell -ExecutionPolicy Bypass -File .\стенд.ps1 -Ботов 3     # три бота разом
```

Снаряд поднимает сервер, вводит в мир сколько скажете ботов, гоняет список
опытов из `стенд-опыты.txt`, печатает сводку числами и прибирает за собой.
Нужен только Windows PowerShell 5.1 — тот, что стоит в системе; ничего
доставлять не надо.

### Зачем он есть

За последние волны **четырежды** находилось, что правило верное, а живой путь до
него не доходит: и набор зелёный, и правило зелёное, а бот живьём делает не то.
Ловится это только живым прогоном, а живой прогон собирался руками: поднять
сервер, дождаться мира, выдрать ключ окна из консоли, войти, слать команды,
читать журнал, прибрать. Один прогон **сорвался** на том, что порт окна был
занят, бот молча встал на соседний, а вход ушёл к чужому боту — тому, что
остался от прошлого раза.

Поэтому снаряд не «запускает два батника», а:

* **ждёт факта, а не секунд.** Сервер готов, когда сам сказал `Dedicated Server
  now running on Port`; бот в мире, когда в его журнале появилось
  «Мир финализирован». До этой строки координаты в командах ещё мировые, и
  «!иди 62 112 249» ушло бы совсем в другую точку мира;
* **берёт порт окна из консоли бота, а не из того, что просил.** Занятый порт
  бот обходит молча (`MiniHttp`: десять соседних), и это ровно та беда, что уже
  сорвала прогон;
* **даёт каждому боту своё хозяйство** — свою папку (`VSBOT_STATE`), свой
  журнал, своё имя и **свой uid**. Uid с завода один на всех
  (`bot-local-uid`), а сервер отличает игроков именно по нему: два бота с одним
  uid — для сервера один игрок;
* **не даёт прогнать вчерашнего бота.** Исходники новее сборки — снаряд
  ПЕРЕСОБИРАЕТ её и говорит об этом; ключ `-СобиратьНе` превращает устаревшую
  сборку в отказ прогона. Заведено по живой беде 26.08: прогон отработал 38
  опытов и отчитался числами, гоняя DLL, в которой первого пункта заказа не было
  вовсе — снаряд проверял только, что файл бота СУЩЕСТВУЕТ;
* **гасит сервер по-хорошему**, а не убивает: говорит ему `/stop` и ждёт, пока
  тот сохранит мир. Не послушался за девяносто секунд — гасит жёстко и вслух
  предупреждает, что мир мог остаться недописанным. Раньше сервер убивался
  насмерть каждый прогон, а он держит мир заказчика;
* **прибирает**: гасит ботов и сервер, дожидается освобождения портов и говорит
  о каждом;
* **не даёт поднять второй сервер на занятом мире.** Свободного порта для этого
  мало: сервер, который ещё грузится и порта не открыл, уже держит
  `Saves\default.vcdbs`. И сам порт спрашивается двумя вопросами — сперва
  «кто-нибудь отвечает?», потом «дадут ли занять»: попытка занять `127.0.0.1`
  удаётся даже тогда, когда чужой сервер слушает `0.0.0.0` на том же номере.

### Что лежит в папке прогона

`out\стенд-<время>\` (в снимок не идёт, `out/` закрыт `.gitignore`):

| файл | что в нём |
|---|---|
| `прогон.log` | всё, что снаряд говорил вслух |
| `сводка.csv` | по строке на бота: точка, опыты, беды, исключения |
| `опыты.csv` | каждый опыт: команда, аргументы, секунды, чем кончился, слова бота |
| `беды.csv` | **строки журнала**, за которые насчитаны признаки беды |
| `бот-N\логи\bot.log` | журнал бота целиком |
| `бот-N\консоль.out.txt` | консоль бота (кодовая страница системы, не UTF-8) |
| `сервер.out.txt` | консоль сервера |

Код возврата: `0` — прогон прошёл без отказов; `1` — прогон прошёл, но есть
отказ; `2` — прогон не состоялся (не поднялся сервер, не вошёл бот, сборка
устарела при `-СобиратьНе`).

**Отказом считается ФАКТ, а не слово в журнале**: исключение у бота, команда, на
которую он не ответил вовсе, или бот, не доживший до конца прогона. Раньше код
ставился сырым счётом подстрок — включая те, что сам снаряд объявляет невинными
(«не дошёл ни разу → крафт», 22 раза из 29), — и здоровый прогон ВСЕГДА давал
`1`. В качестве ворот такое было бесполезно. Счёт слов никуда не делся: он в
сводке и целиком в `беды.csv`, читать его человеку полезно, а решать по нему
нельзя.

### Как пишется список опытов

Строка: `кто ; команда ; аргументы ; срок в секундах`.

* **кто** — `1`, `2`, `3`… (этому боту), `все` (каждому по очереди), `разом`
  (всем одновременно), `пауза` (переждать; секунды во втором поле);
* **команда** — имя команды окна управления, без восклицательного знака;
* **срок** — сколько ждать ответа; пусто — как задано ключом `-ЖдатьОпыт`.

`разом` — это и есть смысл нескольких ботов: заказчик просил их «для
ускоренного тестирования». По очереди они экономят только подъём мира; вместе —
ещё и время опыта, и заодно видно, не мешают ли друг другу в одной двери.

**Особая команда `смещение dx dz`** — это `иди` от **своей** точки, а не от
спавна. Точку снаряд спрашивает у самого бота (окно, `/api/state`). Нужна она
затем, что ходьба по числам вроде `62 112 249` привязана к дому заказчика: в
другом мире там пусто, бот честно скажет «Не дошёл», а снаряд насчитает беду
там, где её нет.

**Особая команда `ксоседу N`** — идти туда, где стоит бот номер `N`. Точку
снаряд спрашивает у **самого соседа**, а не считает: боты ходят, и записанные
числа устарели бы к концу первой же строки списка. Нужна она для передачи вещей
из рук в руки: подойти вплотную, бросить, поднять — ровно как живой игрок.

**Особая проверка `сумка <кусок кода> <сколько>`** — это **не команда боту**, а
вопрос серверу: снаряд берёт опись сумок (окно, `/api/inventory`) и сравнивает
число. Ради неё всё и заведено: «Бросил 1 шт.» и «подобрал: 1» — слова о
*действии*, а не о *результате*, и обе фразы бот скажет и тогда, когда лук
улетел в воду. **Не сошлось — это отказ прогона** (код возврата `1`), а не слово
в журнале; в сводке под это заведена своя колонка «Не сошлось в сумке».

Ключи запуска: `-Ботов`, `-Опыты`, `-ПортОкна` (с завода 42500 — нарочно не
42462, чтобы не трогать бота, запущенного руками), `-ПортСервера`, `-Папка`,
`-Пресет`, `-Имя`, `-Метка`, `-Мир`, `-Сборка`, `-СерверУже`, `-НеПрибирать`,
`-Беды`, `-ЖдатьСервер`, `-ЖдатьОкно`, `-ЖдатьМир`, `-ЖдатьОпыт`.

**`-Мир` и `-Сборка` — про то, что на машине бывает две работы сразу.** Оба
завелись живой бедой 27.08, и обе беды одного рода: снаряд намертво привязан к
`TestServer` и к `VintageBotStory\bin\Debug`, а рядом шла вторая работа —
и первый прогон не состоялся дважды подряд.

* `-Мир <путь>` — своя папка мира (`--dataPath` сервера). Мир держит **один**
  сервер: `Saves\default.vcdbs` заперт, и второй прогон на том же мире
  отказывается — это правильно. Со своей копией мира прогоны не мешают друг
  другу вовсе. Копию делает человек, снаряд её не создаёт и не удаляет (мир
  весит сотни мегабайт). **В копии надо поправить `serverconfig.json` в двух
  местах:** `Port` (иначе два сервера на одном номере) и `SaveFileLocation` —
  он там записан **абсолютным путём на исходный мир**, и копия молча открывала
  бы чужой файл. Прав это не касается: `Roles` и `Playerdata` не трогаются.
* `-Сборка <путь к exe>` — свой файл бота. Заводскую сборку держит открытой
  чужой запущенный бот, и пересборка ложится с `MSB3021` («файл занят другим
  процессом») вместе со всем прогоном. Ставится вместе с `-СобиратьНе`:
  пересобирать чужой каталог снаряд не должен, а свой уже собран.
  Собрать своё: `dotnet build VintageBotStory -p:BaseOutputPath=C:\tmp\своё\`.

### ЧЕГО ЭТОТ СТЕНД НЕ УМЕЕТ

Это не список пожеланий, это границы. Не зная их, легко принять пустой прогон
за удачный.

1. **Он не заведёт зверя и не поставит колокол.** У бота роль `suplayer`,
   серверные команды (`/gm`, `/giveitem`, `/spawnentity`) ему не положены, а
   поднимать ему права правкой `Playerdata`/`serverconfig` запрещено: защита это
   блокирует, обходить нельзя. Значит «расстрелять зверя из лука» и «убить
   колокол с дистанции» **этим снарядом не проверяются**.

   **А ВОТ ЛУК ТЕПЕРЬ ВЫДАЁТСЯ — это перемена 27.08.** Способ подсказал
   заказчик дословно: «и лук со стрелами ты можешь выдать ему другим ботом, не
   вижу проблем». Он был прав, и преграда была не в правах, а в голове:
   **передача вещей между двумя ботами прав администратора не требует вовсе** —
   один бросает, другой поднимает, ровно как живые игроки. Первый лук при этом
   никто не выдаёт: его делает сам бот по рецепту **из реестра сервера**
   (`bow-simple` = 3×`stick` + 3×`flaxtwine`, `flaxtwine` = 4×`flaxfibers`;
   ни одного из этих чисел в коде бота нет). **Про «три» отдельно:** заказ
   волны 27.08 называл четыре палки, и живой бот поправил это в первую же
   минуту прогона — «Для bow-crude не хватает: stick 0/3, rope 0/3». Узор
   рецепта в игре — `_ST S_T _ST`, ровно по три. Опыты стоят в
   `стенд-опыты.txt`, раздел 7, и требуют двух ботов: `-Ботов 2`.

   **Чего это всё ещё не даёт:** решение «дерусь или бегу» показать по заказу
   нечем. Оно считается только тогда, когда рядом и правда есть враг, а завести
   врага снаряд не может; команды, которая печатала бы это решение по имени
   существа, у бота нет ни одной. Значит починка «с луком бот больше не говорит
   „драться нечем“» живьём **не показана** — только стендом без сети.

   **Что для этого должен сделать хозяин мира** — человек, у которого права
   администратора есть. Чем именно (творческий режим, консоль сервера, просто
   передать вещи из рук в руки в игре) — его дело; точных строк серверных команд
   здесь нет нарочно, у бота их всё равно нет, а выдумывать чужой синтаксис в
   этом проекте запрещено. Нужно вот что:
   * **дать боту стрелы** — вот их бот сделать не может, и причина в файлах
     игры, а не в боте. В `assets/survival/recipes/grid/tool/arrow.json` ровно
     два рецепта: обычная стрела просит наконечник, палку и **перо** (а перо
     падает только с курицы или из клада — то есть его надо сперва добыть тем
     самым оружием, которого ещё нет), а безперьевая `arrow-crude` закрыта
     **чертой класса `bowyer`**, которой у бота нет и взять неоткуда. Коды из
     файлов игры, не из головы: `arrow-copper`
     (`assets/survival/itemtypes/tool/arrow.json`, вариантов четырнадцать —
     от `crude` до `steel`). **Лук выдавать больше не нужно** — см. выше;
   * **привести цель.** Зверь: `wolf-eurasian-adult-male`
     (`assets/survival/entities/animal/mammal/wolf-adult.json`, теги `animal`,
     `huntable`, `predator`). Колокол: `bell-normal`
     (`assets/survival/entities/lore/bell.json`) — это **сущность, а не блок**.
     `bellmini-normal` целью не годится: у него нет `spawnconditions` вовсе, он
     спутник селянина, и бот его нарочно не трогает — он назван в ручке роли
     «МирныеКоды» (заводское значение `bellmini`, есть во всех шести пресетах).
     Прежней заплатки `bell-` с чёрточкой в списке начал имён больше нет:
     врага бот узнаёт по МЕТКАМ игры (ручка «ВражескиеМетки»), а колокол и
     колокольчик для клиента неразличимы ничем, кроме имени;
   * после этого опыты ставятся обычными строками списка: `1 ; хп ;`,
     `1 ; кто ;`, `1 ; иди ; …` — снаряд соберёт слова бота и посчитает беды
     как обычно.

   **А ВОТ КОСТЁР ПРАВ НЕ ТРЕБУЕТ, и опыт на него в списке есть** (раздел 5
   в `стенд-опыты.txt`). Бот складывает и поджигает костёр сам; дальше `!блок` на
   его клетку обязан ответить `стоять=False, вред=ЖЖЁТ СТОЯЩЕГО`, а на погасшем —
   `стоять=True, вред=нет`. До 27.08 опыта про огонь не было ни одного, и
   читатель отчёта видел 38 опытов, не находил среди ограничений слова «огонь» и
   заключал, что костёр покрыт. Он покрыт не был.

   Нужны при этом материалы: `firewood` ×4, `drygrass`, `firestarter`. В мире
   TestServer их нет, а добыть их бот не может — дрова колют топором, `drygrass`
   падает только под нож, огниво надо скрафтить, инструментов у бота нет.
   Положите их ему в сумку, и опыт станет полным.

   **ЛАВА И КИПЯТОК НЕДОСТУПНЫ ВОВСЕ.** Встать в них бот по своей воле не может
   (правило вреда не даёт), а налить их некому: `/giveitem` и `/worldedit` роли
   `suplayer` не положены. Уход ИЗ лавы этим снарядом не ставится.

2. **Мир между прогонами не сбрасывается.** Сервер помнит игрока по uid и сажает
   его туда, где тот вышел: второй прогон подряд начинается не со спавна, а там,
   где кончился первый. Нужен чистый старт — задайте `-Метка` (латиница и
   цифры): боты войдут новыми игроками. Ценой того, что в `playerdata` мира
   прибавится по игроку на каждого.

3. **Стенд оставляет след в мире, и это видно в снимке.** Сервер сам при первом
   входе дописывает бота в `TestServer/Playerdata/playerdata.json`: по записи на
   бота, роль `suplayer`, привилегий никаких. Файл этот в снимке есть, так что
   после прогона `git status` покажет его изменённым. Это не правка прав — это
   сервер записал, кто заходил.

4. **Беду он считает по словам, и слова эти иногда невинны.** Признаки с завода —
   `упёрся`, `тупик`, `застрял`, `погиб`, `не дошёл`. Живой прогон сразу показал
   обе стороны: у одного бота вышло «не дошёл = 29», хотя не дошёл он ровно
   один раз (двадцать два раза это было «не дошёл ни разу (точек в обходе 1) →
   крафт: …», то есть разговор про сбор еды), а «тупики не пишу: забаню дверь»
   — вообще не тупик. **Поэтому снаряд не берётся отличать беду от невинного
   слова** (это была бы догадка) и показывает сами строки: в сводку — самые
   частые, в `беды.csv` — все. Число там, чтобы заметить; строки — чтобы
   понять.

5. **Слова бота приходят с запозданием, и один опыт из нескольких десятков может
   получить ответ соседа.** Окно на любую команду отвечает «выполнено»
   (`ControlPanel.CommandAsync`), а настоящий ответ — «Пришёл (62, 112,1, 250)»,
   «Не дошёл — на пути стена или обрыв» — бот говорит **в чат**, и в журнал тот
   попадает, когда сервер разошлёт сообщение обратно. Снаряд ждёт полторы
   секунды тишины (до шести секунд всего) — этого хватает почти всегда, но не
   всегда: в прогоне на 38 опытов один остался с половиной ответа («Иду к» без
   «Пришёл»). Видно это сразу: у такого опыта в квадратных скобках стоит
   `[ответил]`, а не `[дошёл]`.

6. **`все` — это по очереди, а не разом.** Пока первый бот идёт, остальные
   ждут. Одновременность даёт только `разом`.

### Что прогон уже нашёл

Прогон на трёх ботах (27.08, мир `TestServer`, 38 опытов, **186,8 с**, один
подъём мира) дал три находки, и все три — живые; повторились они в каждом из
пяти прогонов:

* **бот в воде у (32, 113, 4) не уходит оттуда никуда.** Четыре ходьбы из
  четырёх — «Не дошёл — на пути стена или обрыв», в журнале раз за разом

  трёх прогонах подряд, клетка та же;
* **дверь (62, 112, 252)**: «затор в дверном проёме (62, 112, 252) в тупики не
  пишу: забаню дверь — отрежу себе вход». Проход при этом состоялся;
* **бот берётся за дела посреди опыта**: «Сейчас занят: бой. Повтори позже»,
  «Сейчас занят: поход за лечебным. Повтори позже». Окно на такое отвечает
  «выполнено», и без разбора слов бота опыт выглядел бы удачным. Отсюда в сводке
  отдельный счёт «Был занят».

## Роль, пресет и конструктор — что чем отличается

Это три разных слова, и путать их дорого.

* **Роль — это КОД.** Она умеет то, что умеет: копать карьеры, торговать по
  табличкам, думать нейросетью. Настройкой новое умение не появится.
* **Готовый бот (пресет) — это ТЕКСТ.** Файл в папке `presets`: он называет
  роль и все её настройки. Пресетом можно делиться — адреса сервера, имени,
  токена, пароля и ключа нейросети в нём нет и быть не может.
* **Конструктор роли — вкладка в окне управления.** В ней вы собираете
  готового бота: берёте роль, крутите её настройки и сохраняете файлом. Бота,
  который работает прямо сейчас, это не трогает вовсе.

Ролей в поставке четыре, и у каждой своё:

| Роль | Кто это | Чего нет у других |
|---|---|---|
| `survivor` — Выживальщик | Живёт сам; по приказу — карьеры, штольни, руда, дороги | размер и глубина карьера, разведка, штреки, самородки, наряды |
| `trader` — Продавец | Стоит в лавке, обходит прилавки, торгует по табличкам | торговля и цена спрыгивания с высоты |
| `ai` — ИИ | Решения принимает нейросеть теми же умениями, что человек в чате | поставщик, модель, усилие, потолки трат, характер, цель и правила |
| `guard` — Стражник | Стоит на посту, кормится со склада, не пускает по списку ников. **Без нейросети** | точка «Пост» и поводок от неё, список запрещённых ников, радиус охраняемой зоны, что говорить чужому, кого звать, бить ли |

Точные числа — во вкладке **«Готовые боты»**: рядом с каждой ролью стоит,
сколько у неё настроек всего и сколько таких, каких нет ни у одной другой.
Это и есть ответ на «а чем они отличаются». А сами эти настройки — во вкладке
**«Настройка роли»**: там лежит своё у выбранной роли — и вместе с ним шесть
ручек, которые есть у ВСЕХ ролей, но задаются каждому боту отдельно: «Склад»,
«Дом», «СоседниеСундукиВРадиусе» и три ручки рейса на склад —
«РазгружатьсяСам», «РазгружатьсяПриСвободныхМестах»,
«ПовторРазгрузкиЧерезСекунд». Держать их рядом просил заказчик дословно:
«сохранение склада и дома давай на одной странице настроек — в настройки роли».
Всё прочее — то, что есть и у других ролей, — соседней вкладкой, «Общие
настройки».

**Делят их по РОДСТВУ, а не по темам** — и перечислять темы тут нельзя вовсе.
Одна и та же тема живёт на обеих вкладках сразу: своя ручка роли остаётся у
роли, даже когда рядом, среди общих, стоят её однофамильцы от других ролей.
Что где лежит, показывает сама вкладка — заголовками разделов и счётчиком у
каждого; пересказ этого словами трижды подряд оказывался враньём.

**Готовый бот другой роли меняет роль на ходу.** Нажали «Выбрать» — бот
собирает новую роль, откатывает поля старой и говорит в окне, что вышло: «роль
сменил на ходу, перезапуск не нужен» — или, если прежняя роль вернулась не вся,
называет поимённо, что не вернулось, и просит перезапустить. Выбранное
запоминается в `bot.json`. Что из настроек действует сейчас же, а что — со
следующего входа на сервер, окно помечает у самой настройки.

### Как собрать своего бота в окне

Вкладка **«Конструктор роли»**.

1. **Из чего собирать.** Выберите роль. Хотите править уже собранного —
   выберите его в соседнем списке: настройки возьмутся у него, а роль он
   назовёт сам.
2. **Крутите настройки.** Галочка включает и выключает умение, число задаёт
   предел, три поля задают точку. Под каждой настройкой стоит её собственное
   объяснение, написанное в роли, — окно его не сочиняет. «Главное» показывает
   то, что роль назвала главным сама; «Все» — и редкое.
3. **Сохраните.** Имя латиницей — это имя файла и имя в ключе `--preset`.
   Файл ложится в вашу папку пресетов, а не в ту, что приезжает с программой:
   ту перезапишет обновление.
4. **Выберите и перезапустите** — вкладка «Готовые боты».

Ничего из набранного в конструкторе не уходит боту, пока вы не нажали
«Сохранить». Живого бота правят на двух соседних вкладках — «Настройка роли»
(своё у этой роли плюс «Склад», «Дом», «СоседниеСундукиВРадиусе»,
«РазгружатьсяСам», «РазгружатьсяПриСвободныхМестах» и
«ПовторРазгрузкиЧерезСекунд») и «Общие настройки» (всё остальное); там каждая
ручка уезжает к нему сейчас же.

**Чего конструктор не делает.** Он собирает СУЩЕСТВУЮЩЕЕ. Новых умений в нём
не появляется: если бот чего-то не умеет, ни одна галочка этого не добавит.
Пример из жизни: «не пускать в город по списку ников» из готового собрать было
нельзя — такой способности у бота не было вовсе, и `presets/guard.json` собирал
сторожа НА НЕЙРОСЕТИ, которому список ников объясняли словами в правилах.
Теперь способность написана кодом, и стражник — своя роль `guard` без всякой
нейросети (см. ниже). Это и есть общее правило: чего нет — то пишется кодом, а
не изображается настройкой.

## Стражник: что он вправду может, а чего не может никто

Заказ был такой: «стоять в одной точке, кушать со склада и не пускать людей по
списку». Первые два дела собраны из готового, третье написано кодом. А вот
слово «не пускать» надо понимать точно, потому что здесь легче всего обмануться.

**Бот — живой игрок, а не сервер.** Чужим движением он не распоряжается: в игре
нет ни клиентского способа запретить человеку идти, ни игрока, который собой
перегораживает проход (столкновения считаются с блоками мира, а не с чужими
телами). Всё, что вправду «не пускает», делает СЕРВЕР: бан, кик, привилегия на
клейм. Роль этого не обещает.

**Что стражник делает:**

* видит, кто рядом, и читает имена;
* называет пришедшего по имени в общий чат: «Гриша_Вор, тебе сюда нельзя»;
* зовёт хозяина, назвав его ником;
* **бьёт — только если это прямо велено** ручкой «Бить». Заводское — НЕТ:
  драка со «своими по списку» это решение хозяина сервера, а не наше.

**Чего он не делает нарочно:** не встаёт на пути (телом чужого не остановить —
это был бы театр), не банит и не кикает (права сервера). Если хозяин даст боту
админские права, `/ban ник` из чата у него сработает так же, как у живого
админа, — но это отдельный заказ, и молча такого не делают.

### Как поднять стражника

```bash
VintageBotStory --preset guard --panel
```

Перед запуском заполните три вещи:

1. **Пост** — это СВОЯ ручка стражника «Пост» (вкладка «Настройка роли»,
   карточка «Стража»), или щелчок по карте, или команда в чате `!пост тут`.
   Вокруг этой точки считается охраняемая зона, и от неё же он не отходит
   дальше «ОтходитьОтПостаНеДальше».

   **«Пост» пуст — зона считается вокруг «Дома»**, ровно как до 23.08, а
   удержание точки молчит и один раз честно говорит в журнал, какой ручки не
   хватает. Пустой «Пост» — это не поломка, а прежний стражник. Не задан ни
   «Пост», ни «Дом» — охранять нечего, и об этом тоже будет сказано вслух.
   Заполните обе точки РАЗНЫМИ местами вместе с «БезДела: Домой» — и бот
   станет ходить между ними; в `presets/guard.json` поэтому стоит
   «БезДела: Стоять».
2. **Список ников** — вкладка «Настройка роли», поле «ЧужиеНики», через
   запятую. Имя сравнивается ЦЕЛИКОМ и без оглядки на регистр: «Вася» накрывает
   «вася» и не накрывает «Василия». Пустой список никого не запрещает, и об
   этом тоже будет сказано вслух.
3. **Ваш ник** — поле «Хозяин»: к кому стражник обращается, увидев чужого.

Еда: чтобы стражник кормился со склада, задайте ручку **«Склад»** — вкладка
«Настройка роли», прямо под ней «Дом», — или скажите `!склад тут`, стоя у
сундука с едой. Ручка эта есть у ВСЯКОЙ роли, стражник не исключение; рядом с
ней стоит «СоседниеСундукиВРадиусе» — сколько соседних сундуков идёт под склад
вдобавок к названной точке (по умолчанию 6 блоков, ноль означает «склад ровно
один сундук»).

Команда `!стража` в чате отвечает, где пост, какая зона, кого он не пускает и
велено ли бить.

## Своя роль кодом: что за файл, куда класть, с чего начать

Роль — это класс-наследник `BotRole`. Свои роли бот ищет **собранными файлами**
(`*.dll`) в папке `roles` и берёт их в тот же список, что и наши четыре: своя роль
видна в окне, выбирается пресетом и настраивается тем же конструктором.

**Почему собранный файл, а не исходник.** Компилятора внутри бота нет: он
раздаётся одним самодостаточным файлом, и тащить туда .NET SDK ради этого
незачем. Собираете вы у себя, одной командой.

### С чего начать — по шагам

1. Заведите библиотеку классов:

   ```bash
   dotnet new classlib -o МояРоль
   ```

2. В `МояРоль.csproj` добавьте ссылку на библиотеку бота. Есть исходники —
   ссылкой на проект; есть только собранный бот — ссылкой на файл:

   ```xml
   <ItemGroup>
     <Reference Include="VsBotKit">
       <HintPath>путь\к\VsBotKit.dll</HintPath>
       <Private>false</Private>
     </Reference>
   </ItemGroup>
   ```

   `Private=false` — чтобы копия `VsBotKit.dll` не легла рядом с вашей ролью:
   про такую копию бот скажет вслух и возьмёт роли не из неё.

3. Напишите роль. Меньше этого не бывает:

   ```csharp
   using VsBotKit;

   namespace МоиРоли;

   public class Сторож : BotRole
   {
       public override string Name => "Сторож";

       // Публичное свойство, которое можно записать, — это НАСТРОЙКА роли.
       // Она сама появится в окне и уйдёт в пресет.
       public string ЗапрещённыеНики { get; set; } = "";

       public override void Configure(VsBot bot)
       {
           bot.Survive();        // рефлексы выживания одной строкой
           bot.CommonCommands(); // обычные команды чата
       }
   }
   ```

4. Соберите и положите файл:

   ```bash
   dotnet build -c Release
   cp bin/Release/net10.0/МояРоль.dll <папка бота>/roles/
   ```

5. Перезапустите бота. Во вкладке «Готовые боты» появится строка
   `сторож — Сторож — своя роль из файла «МояРоль.dll»`, а под списком — что
   именно бот взял и что отверг.

### Что бот требует от класса

Все четыре условия он проверяет и о каждом отказе **говорит вслух**:

* класс **публичный** — иначе снаружи его не создать;
* **не абстрактный**;
* есть **конструктор без аргументов** — бот не знает, что ему передать;
* наследник **`BotRole`**.

**Имя роли для настроек** (`--preset`, список в окне) берётся от имени класса в
нижнем регистре: `Сторож` → `сторож`. Имя для человека говорит сама роль —
свойство `Name`. Если такое имя уже занято нашей ролью, чужой файл её **не
отнимает**: бот откажет вслух и оставит нашу.

**Настройки роли** — это её публичные свойства, которые можно записать.
Понимаются флаг, число, строка, перечисление (в окне станет списком) и точка из
трёх чисел (`GamePos?`, `BlockPos?`). Метка `[KnobPlace("работа")]` рядом со
свойством говорит, в каком разделе окна ему стоять; без метки бот разложит по
словам и честно пометит, что раздел выбран догадкой. Текст `/// <summary>` над
свойством станет объяснением под полем в окне.

### Где бот ищет папку `roles` — по порядку

Роли берутся **из всех** этих папок, а одна и та же папка называется один раз.

1. То, что сказано переменной окружения `VSBOT_ROLES` (путь ДО папки с файлами
   ролей).
2. **Рядом с проектом** — только если бот запущен из папки сборки
   (`…\bin\Debug\net10.0`). Там же, где `presets`: всё, что лежит в `bin`,
   стирает пересборка.
3. Папка состояния бота — там же, где `bot.json`.
4. Рядом с исполняемым файлом — то самое «положить в папку с ботом».

Папки нет — бот молчит: у большинства хозяев своих ролей и не бывает. Папка
есть, но пуста — скажет.

### Честно об опасности и о границах

* **Файл в `roles` — это КОД, и он пойдёт в том же процессе, что и бот.** Он
  может всё то же, что бот: читать ваши файлы, ходить в сеть. Песочницы тут нет
  и быть не может. Кладите туда только то, что собрали сами.
* **Копию `VsBotKit.dll` или самого бота в `roles` класть не надо.** .NET вернёт
  уже поднятую сборку, роли возьмутся не из вашего файла, и правки в нём ничего
  не изменят. Бот про это скажет — но лучше просто не класть.
* **Перезагрузки на лету нет.** Положили файл — перезапустите бота.
* **Исходники `.cs` бот не собирает** и собирать не будет.
* Проверено сборкой отдельной роли и её подхватом из папки на Windows. На Linux
  и macOS своя роль не запускалась ни разу — как и сам бот.

## Чего это НЕ делает

- **Игру за вас не поставит.** Бот — не отдельная игра, он клиент к ней.
- **Без установленной игры не работает вовсе**, и обойти это нечем: код
  распаковки пакетов, реестра блоков и физики — игровой. Сборку сжатия нельзя
  заменить пакетом из NuGet: чистый .NET-порт (`ZstdSharp.Port`) есть, но
  подменять нечего — вызовы объявлены внутри игровой сборки, и своего
  «разрешателя» туда не поставить (.NET разрешает ровно один на сборку, и он
  уже занят самой игрой; проверено — второй роняет игровой код).
- **Пароль от аккаунта нигде не хранится.** Ни в одном файле: только
  переменная окружения `VS_PASSWORD` или ввод в окне, который проходит
  насквозь и забывается. Сохраняется лишь ключ сессии — в `botsession.json`,
  с правами 600 на Unix.
- **Ключ нейросети — единственный секрет, который окно вправду кладёт на
  диск.** Файл `botsecrets.json` в папке состояния бота (там же, где
  `bot.json` и `botsession.json`), права 600 на Unix; **не зашифрован** — как и
  ключ сессии рядом, и по той же причине: шифровать пришлось бы ключом, который
  лёг бы туда же. Кто имеет доступ к папке состояния — имеет доступ и к ключу.
  Наружу значение не отдаётся никогда: окно показывает только «ключ есть» или
  «КЛЮЧА НЕТ», в журнал и в чат ключ не попадает, в файл готового бота — тоже.
  **Переменная окружения `ANTHROPIC_API_KEY` остаётся и она старше:** задана
  она — работает она, а сохранённое в окне ждёт своего часа, и окно об этом
  говорит прямо. Задаётся ключ во вкладке «Настройка роли», карточка
  «Нейросеть»; пустое поле означает «забыть». Уже запущенный бот нового ключа
  не подхватит — клиент нейросети читает переменную один раз, при создании.
- **Проверено сборкой и запуском на Windows.** Файлы для всех четырёх систем
  собраны с одной Windows-машины; запуск, копирование библиотеки сжатия и
  окно управления проверены на Windows живьём. На Linux и macOS живьём не
  запускал никто из нас.
